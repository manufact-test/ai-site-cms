## 4. Текущий большой заход — локализованная публикация и реальная форма

Начиная от зелёного `d9397a...`, работа распределена по:
- `stage3/server/PublicRenderer.php`: UI опубликованной страницы на всех шести поддерживаемых языках (`ru,en,pl,de,be,uk`): мобильное меню, aria-навигация, «Назад/Далее», многоэтапный progress, локализованные страницы статического перенаправления. Эти строки являются закрытым first-party словарём, не пользовательским HTML.
- Тот же `formStepsScript()`: многошаговую форму можно проходить клавиатурой/Enter; скрытый следующий шаг больше не мешает преждевременной браузерной валидацией. Перед финальной отправкой явно проверяются **все поля всех шагов, активные условные поля и обязательное согласие** с использованием нативного `checkValidity()`. Переход между шагами доступен с фокусом на текущем `legend`; `aria-current` и visible focus outline. Если JS отключён, остаётся обычный HTML с нативной браузерной валидацией.
- `stage3/runtime-export/bin/build.cjs`: в независимый Next package при сборке записывается `lib/wizard-contract.js` с SHA-256 **точного скрипта из доверенного PHP-публикатора**. Независимый пакет всё ещё не содержит PHP CMS, приватную базу и секреты.
- `stage3/runtime-export/templates/next/lib/runtime.js`: запуск только скрипта, который **полностью** соответствует SHA-256 trusted PHP-публикатора, с route-specific Next Script ID, чтобы при переходе между страницами React не пропускал инициализацию.
- `stage3/tests/server-e2e.cjs`: реальный опубликованный польский wizard, локализованная навигация и static redirects, проверка сгенерированного Next script hash для Static и SSR.
- `stage3/tests/approved-site-browser.cjs`: узкий реальный Chromium-сценарий клавиатурного прохождения польской multi-step формы: Enter/Back, условное обязательное поле, согласие, успешная отправка только после валидации.
- Прямое подтверждение email collector, anti-spam, приём заявок и самостоятельные release-маршруты не переписаны.

**Важное:** за текущий заход были промежуточные отменённые/красные Actions из-за новой проверки и порядка вычисления `$language`; PHP был исправлен, переводы в старом тесте обновлены. Признавай завершённым ТОЛЬКО последний Actions, чей `head_sha` строго равен HEAD ветки и оба задания `SUCCESS`. Если новому чату досталась незавершённая CI-проверка, сначала закончи её/исправь лог, затем продолжай продукт. Нельзя выдавать промежуточный зелёный коммит за финал.

Нет реального owner-approved макета — не ставить `ownerAccepted`, не объявлять pixel-perfect, не закрывать environment gates. `main`, prod, Hostinger, CELIKOM, SEO ветка, PR/merge — НЕ трогать.
