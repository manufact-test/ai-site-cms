## Главная цель
Это лёгкая CMS для индивидуальных сайтов, созданных **внешним ИИ-разработчиком после фактического одобрения** клиентом трёх статичных макетов. Внешний ИИ изучает нишу/UX/SEO, готовит картинки desktop/tablet/mobile, поясняет клиенту кнопки, анимацию, структуру/адаптив, даёт внутреннюю инженерную спецификацию; только после реального утверждения пишет полный сайт в типизированном `site.json` с реальными медиа. CMS подключает, редактирует и публикует его — **не** генерирует сайты, не универсальный Elementor и не шаблонная фабрика. Сайты сохраняют уникальный дизайн, без импорта произвольных HTML/JS/PHP.

Обязательные источники: [MASTER](../../docs/MASTER-TZ.md), [ROADMAP](../../docs/ROADMAP.md), [APPROVED FOLDER SPEC](../../stage3/docs/APPROVED-SITE-PACKAGE.md), [CODE SCOPE AUDIT](../../docs/CODE-SCOPE-AUDIT-2026-10-27.md), `requirements/requirements.csv` (исторически 193 пункта: 135 обязательных, 42 желательных, 16 не нужно). При противоречиях MASTER имеет продуктовый приоритет; статус кода проверять в HEAD.

## Что действительно реализовано
1. **Safe custom contract:** версионированные манифесты, индивидуальные `custom-section@1.0.0` с обязательным закрытым typed Design Graph, responsive design, motion/hover/focus в пределах безопасной модели. JS Studio и реальный PHP renderer. Никакого произвольного пользовательского PHP.
2. **Portable sealed external handoff v2:** `stage3/bin/seal-approved-site.cjs`, `verify-approved-site.cjs`, `audit-approved-site.cjs`. Обязательны signed-by-hash `handoff.json`, `site.json`, 3 статических макета homepage, client-explanation и implementation-spec, фактические media bytes. Опционально `files.pagePrototypes`: ещё 3 независимых изображения для каждого из до 20 внутренних page.id. SHA-256 фиксирует байты, **не является подписью клиента**.
3. **Owner Studio:** полный диалог проверки исходных картинок рядом с рендером каждой выбранной страницы на desktop/tablet/mobile ДО серверной записи, явный отказ, затем импорт отдельного неопубликованного сайта (пошаговая загрузка медиа, возобновление exact sealed package без подмены при прерывании). Редактирование текста, изображения, Design Graph/стилей/адаптива, SEO, FAQ add/delete/reorder, медиа, Save, Publish и rollback.
4. **Real PHP launch review:** читает черновик на трёх ширинах по каждой странице, изображения и горизонтальные overflow; отдельно сравнивает с действующей публикацией и с её **собственным** оригинальным утверждённым макетом. Отсутствующий per-page оригинал не подменяется homepage. Человеческие manual signoffs, export JSON с SHA/версией/реально просмотренными страницами. Это НЕ pixel-perfect автоматическая гарантия.
5. **Owner-only immutable evidence vault:** все исходные файлы sealed v2, их версии и SHA; per-page по запросу (без загрузки 60 огромных фото при открытии), скачивание, дозагрузка, защита от перезаписи. Для старой Stage3 DB есть специальная CLI миграция `STAGE3_ALLOW_APPROVAL_UPGRADE=YES php stage3/server/bin/upgrade-approval-evidence.php`. На production её НЕ запускали.
6. **Complete private backup-v2:** история, публикации, media, submissions и approved source evidence, preflight SHA256 всего файла+original ledger, восстановление одной транзакцией на **новый неопубликованный** siteId. Исходные sealed bytes остаются неизменными, поддержан legacy backup-v1. Честный строгий 64 MB JSON-предел (сверх него явная ошибка).
7. **Последний большой проход:** все PNG/JPEG/WebP источники и до 3 responsive вариантов принимаются до **1 000 000 байт на файл** вместо 450KB; PHP upload/renderer, editor, медиа-обработка, offline sealing/verification, full backup/restore согласованы; исходные SHA/размеры/MIME по-прежнему проверяются. Есть сквозной HTTP/SQLite опыт с реальным PNG ~577КБ и восстановлением byte-identical, не превышая новый лимит; >1МБ отвергается. В import-review и офлайн pilot audit — объём фото/макетов, предупреждение о вероятном превышении 64MB полного backup. 4096px, single package 100MB, approved mockup до 8MB остаются.

## Состояние и честные незакрытые ворота
- **Нет настоящего переданного externally-AI-authored клиентского approved пакета и нет клиентского/owner GO**. Прежние E2E проверяют **синтетические** пакеты. Зелёный CI — системная целостность, не соответствие реальной авторской верстки макету.
- Невозможно обещать неограниченную выразительность: если клиентский дизайн требует отсутствующих элементов/поведения, расширять именно безопасный typed contract + PHP + Studio в одном большом pass; не подменять макет generic sections и не допускать raw HTML/JS.
- Ограничение **64 MB на весь backup-v2** может быть существенно для 20 внутренних страниц и нескольких версий макетов. Нет безопасного автоматического split-backup; предупреждение до импорта — **не решение** переполнения. При настоящем пакете измерить фактический объём; при необходимости большая целостная реализация разделённого защищённого экспорта с подтверждённым restore, отдельно от существующего v2, без смены формата/доверия вслепую.
- Import creates an initial unpublished seed and uploads asset bytes in stages; interrupted import may leave recoverable seed. **Это не атомарный all-or-nothing импорт**. Существует signed same-tab retry, нет гарантии recover after clearing session. Не обещать больше.
- Требования «135 mandatory» не приняты целиком; не показывать фальшивый процент готовности. Ранний просмотр одного законченного сайта и его UX-правки владельцем приоритетнее накопления лабораторий.
- После текущего docs-коммита GitHub Actions проверить **актуальный HEAD** по `stage3-ai-contract.yml`; предыдущий код на `4a981e603308f47cd9080816a7eb59a8b32f3390` прошёл, перед документами появился `8c7bf255...` для capacity hint.

## Следующий большой рабочий заход — без дробления
**Первый приоритет:** одна реальная approved-v2 папка от внешнего разработчика после подтверждения клиентом (или выбранный владельцем первый продуктовый pilot). Путь целиком: `verify→audit→Studio review всех исходников→import→редактирование реального H1/фото/ALT/адаптива/FAQ/SEO→Save→реальный PHP review всех страниц/3 ширин→Publish→публичная проверка→rollback→complete backup→isolated restore`. Проследить семантику/интерактив/медиа и фиксацию manual discrepancies. При входном ограничении на 64MB не обещать автоматически успешную полную копию.

**Если реального пакета ещё нет:** работать без лишних «фиктивных клиентов» над одной крупной действительно нужной product vertical из MASTER/135 обязательных, например безопасная масштабируемая полная backup/recovery стратегия для настоящих больших пакетных сайтов или недостающие first-party элементы для действительно индивидуальной верстки, с реальным owner-use workflow. Не ждать пользователя ради мелких согласований; спросить лишь если без оригиналов невозможно утверждать визуальную точность.

**Интеграция SEO второго чата:** только после передачи его финального SHA/ready-to-integrate сообщения; сравнить контракты, тесты, ручная интеграция без правок его рабочего каталога в процессе. Без merge/deploy без отдельного решения.
