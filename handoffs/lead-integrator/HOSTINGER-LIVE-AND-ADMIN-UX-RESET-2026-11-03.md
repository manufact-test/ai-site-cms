### Proposed IA and strict location for functions
A. GLOBAL CMS home (no active site): “Мои сайты” list or honest empty state. Show no fake selected site, pages, sections, draft-saved badge or publish actions without a loaded real site. Distinguish onboarding “Подключить утверждённый сайт” from site creation: the CMS does not automatically build a design or convert arbitrary PNG; show required approved-v2 directory, readiness, preflight, file picker after user explicitly selects an import action. If technical demo exists, show separate clearly labeled “Демо” not as real site and do not silently delete persisted demo.
B. PROJECT/SITE dashboard once selected: site name/domain/status and high-level actions open editor, site settings, pages, media, leads, SEO, publication/history, maintenance as separate purposeful routes/panels. Site settings = identity/domain/navigation/global colors/typography/layout SEO. Media/Leads = site-level management, not imported-site onboarding.
C. PAGE VISUAL EDITOR: clear top toolbar with current site/page, desktop/tablet/mobile, undo/redo, Save draft, Preview, Review, Publish; left pages/sections/layers tree ONLY of selected real page; large live canvas; contextual inspector when element selected (content/style/layout/responsive/interactions). Selecting an element must not expose account, database, CMS-update or unrelated global settings. Other panels collapsed, not giant nested drawers. Distinguish unsaved vs saved draft vs published. Contextual properties, keyboard focus, responsive widths and legible labels.
D. ACCOUNT area: profile, password change, logout, personal preferences, sessions, role. NEVER inside import dialog or block inspector.
E. PLATFORM/ADMIN area (owner-only): users/roles, audit log, licenses, signed CMS updates, recovery, backups, global diagnostics and deployment-sensitive tasks. A deliberate global settings/maintenance route, separate from per-site content and import; guard irreversible operations.
F. Site-level advanced administration: form delivery, media inventory, reusable blocks, backup and site transfer in dedicated site tools under clear navigation. Don't conflate with platform updates/account security.
Reference rationale (official documentation observed Nov 2026): Elementor editor uses toolbar + panel + canvas and distinct panel contexts (widgets/site/page/user preferences/history); current site settings centralized.
