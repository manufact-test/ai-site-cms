## 4. Схема, запуск и проверка

Новые таблицы: `stage3_access_users`, `stage3_site_grants`, `stage3_audit`; исходная `stage3_users` хранит только password hashes. Новая пустая схема через прежний CLI `setup.php` создаёт всё сразу. Старые lab DB **не** изменяются при web request. Для ранее созданной выделенной Stage3 DB есть явная команда:

```sh
STAGE3_ALLOW_ACCESS_UPGRADE=YES php stage3/server/bin/upgrade-access.php
```

Требуется заранее заданный private `STAGE3_DSN` именно выделенной лаборатории. Не выполнять на реальном хосте без нового разрешения. Upgrade additive/idempotent, допускает повтор после частичного DDL; наследует владельца только при одном legacy account и отсутствии access records. Неоднозначные владельцы не повышаются автоматически. Старым сессиям потребуется повторный вход. Production migration/rollback и общий installer ещё не приняты. CLI setup не перезаписывает существующую схему.

Финальный existing workflow `.github/workflows/stage3-ai-contract.yml`, run **40019059962 SUCCESS**, source **964e6746db7680c064cce502ae034c00683115b5**: SDK + deterministic recipes, bundle parity, offline Chromium, PHP8.3 syntax, HTTP/SQLite, hosted Chromium.
