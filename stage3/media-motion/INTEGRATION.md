## Contract

`bundle.json` has the exact enumerable top-level keys:

```
{
  "format": "media-motion-bundle-v1",
  "assets": [{"id":"asset-0001","name":"...","alt":"...","caption":"...",
    "focal":{"x":50,"y":50},
    "original":{"mime":"image/png","width":1024,"height":768,"bytes":12345,"sha256":"64-lowercase-hex"},
    "variants":[{"file":"media/asset-0001-720.webp","mime":"image/webp","width":720,"height":540,"bytes":45678,"sha256":"64-lowercase-hex"}] }],
  "galleries": [{"id":"gallery-main","title":"Gallery","layout":"grid|masonry|carousel","assetIds":["asset-0001"],"columns":3,"motionId":"motion-main"}],
  "motions": [{"id":"motion-main","preset":"fade|slide-up|slide-left|scale|reveal|stagger|hover-lift|focus-ring|none","duration":440,"delay":0,"easing":"ease-out","distance":24,"trigger":"load","mobile":"on"}],
  "icons": ["image","play"],
  "video": {"provider":"none|youtube|vimeo","url":"","posterAssetId":null,"aspect":"16:9"},
  "css": "deterministic vetted CSS string"
}
```

This schematic has abbreviated hash placeholders and enum notation and **is not itself valid JSON**. Use `examples/sample-bundle.json` for a machine-valid empty example and `node -e "require('./stage3/media-motion/lib/contract.cjs').validateBundle(JSON.parse(require('fs').readFileSync('bundle.json')))"` for actual validator invocation.

Closed validator accepts **no unknown keys** at each level, checks IDs, allowlisted MIME/relative `media/` file paths, SHA256 format, bytes/dimensions, no upscaling, unique IDs/paths, gallery references, icon tokens, allowed video URLs, and an exact CSS match to `motionCSS(motions)`. Actual binary SHA256/MIME/byte count are verified by the browser before archive download; the integrator must repeat these checks server-side on import. Empty `assets` in the included sample is configuration-only and not a publishable gallery.

ZIP members: `bundle.json`, `motion.css` and `media/<asset-id>-<width>.<png|jpg|webp>`, all stored without ZIP compression. ZIP CRC32 and SHA256 are both present; server should reject path traversal, symlinks, duplicate zip entries, zip bombs/oversized archives, mismatched hashes, invalid images and over-budget resources. Do not use a naive ZIP extract; verify names, size and magic/decode first and only write into disposable protected upload storage.

`lib/contract.cjs` exposes `validateBundle`, `motionCSS`, `srcset`, `normalizeVideo` and enums, usable in Node. Its strict validation is suitable as a **client-side preflight**, not a server trust boundary. A PHP validator may be translated after review; the shared `site-v1` SDK must not be silently widened.

## Existing CMS mapping / required adapters

| Bundle concept | Already supported in current CMS | Mapping and remaining work |
|---|---|---|
| `asset.id`, variant's image MIME, ALT | `site.assets[]` contains `id,src,alt,mime`; PHP host media accepts PNG/JPEG/WebP <=450 KiB | After an authenticated server-side upload of **one verified chosen variant** for each use, map the **server-issued media ID/path** to `site.assets`. Never directly set `/media/..` as CMS `src`; existing CMS expects `/assets/<id>.<ext>` and its own storage / publication process. |
| `asset.caption` | Some existing gallery item manifests use `content.caption` | Match a gallery item and its asset `content.media` reference only where the registered first-party component declares that field. |
| multiple variants + `srcset` / `picture` | **Not presently supported** | `integration_required`: add private derivative storage, immutable version binding, CDN-independent `picture/srcset` renderer and release export hashes; existing `site.assets` has only single src/mime. `contract.srcset(asset)` returns a verified relative declaration string; do not use it as an untrusted raw HTML slot. |
| crop + rotate + encoder | Existing CMS can import a final processed PNG/JPEG/WebP <450 KiB | Final baked variant can be uploaded as normal image. Preserve metadata (original hash / focal) only in a versioned first-party extension explicitly reviewed by lead. |
| focus `{x,y}` | No current `site.assets` focal field | `integration_required`: typed rendering field, if needed for responsive object-position; crop rectangle is baked in the generated bytes. |
| gallery Grid | Current first-party `photo-gallery` exists | Map item refs to registered `content.media` fields; grid is the nearest baseline. Requires explicit adapter and stable item IDs. |
| gallery Masonry / Carousel | No matching first-party contract or server renderer | `integration_required`: new manifests + Studio controls + PHP/static renderer + accessible keyboard/scroll-snap + deterministic public CSS. Do NOT invent `layout` under existing `site-v1` asset/page. |
| motion presets + CSS | Section `appearance` enums exist but **not** these motion fields | `integration_required`: first-party motion manifest/registry or typed extensions, validated CSS emission to public renderer, reduced-motion enforcement and release-auditor review. Existing export rejects arbitrary active JS, so publish CSS only; never inject optional preview JS. |
| icon tokens | No arbitrary third-party SVG upload | `integration_required`: immutable first-party icon registry and a renderer that maps tokens to vetted vector paths, never user SVG markup. |
| video poster + allowlisted embed address | Video-specific fields not defined in existing components | `integration_required`: choose vetted server-side URL normalization / CSP / privacy policy and explicit renderer, or use safe external link. No automatic remote iframe during standalone preview. |
| `bundle.css` | Exporter's public CSS generated internally | Requires reviewed renderer work to include **only** canonical CSS from `motionCSS`. Do not allow arbitrary CSS or `style` content from uploaded JSON. |
