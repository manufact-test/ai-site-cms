## Миссия — ОДИН очень большой, полный продуктовый пакет

Создай автономный **Media & Motion Workbench** — действительно работающий локальный browser-продукт и повторно используемые библиотеки для будущей интеграции в AI Site CMS, соответствующий направлению Этапа 7 дорожной карты: изображения, адаптивные версии, галереи, иконки, видео-настройки и безопасная анимация. Это не отдельный короткий эксперимент, не набор мокапов/тестов, не «столько-то файлов ради отчёта». Полностью закончи связанные функциональные подсистемы до передачи, с настоящим визуальным интерфейсом и работающими экспортами, не разменивай работу на быстрые микрокоммиты. Структура внутри `stage3/media-motion/` на твоё усмотрение.

### 1. Настоящая браузерная медиабиблиотека

В отдельной standalone offline странице (которую можно открыть локально, без backend и без CDN) реализовать: dropzone и выбор нескольких файлов; галерея миниатюр; выбор, поиск, сортировка, удаление, повторное редактирование; имя, ALT и подпись; размер в пикселях, MIME, вес, оценка пригодности к публикации; уведомления об ошибках. Поддержка только PNG/JPEG/WebP для байт изображения; доказуемая проверка фактического типа/декодирования, лимитов ресурсов и защит от подозрительно огромных/битых файлов. Никаких SVG-файлов от пользователей, небезопасного HTML в подписях или использования `innerHTML` с недоверенными строками.

### 2. Рабочий редактор изображений, не имитация

Crop с перемещаемой областью и пресетами 1:1 / 4:3 / 16:9 / свободный; поворот, точка фокуса X/Y (0–100), превью реального результата; масштабирование и resize, преобразование PNG/JPEG/WebP с реальными downloadable Blob файлами через Canvas; quality и разумное автоматическое уменьшение размера/качества под лимит CMS **450 KiB на итоговый опубликованный файл**. Если невозможно корректно уложиться — честная ошибка, не выдавать повреждённые файлы за успешный экспорт. Показать до/после: размер, разрешение, тип. Никаких внешних image APIs.

### 3. Адаптивные изображения и пакетная обработка

Создание responsive variants по нескольким реально вычисляемым размерам (например 360/720/1200 с сохранением пропорций и без фальшивого upscaling), каждому настоящие bytes/MIME/SHA256; вариант `picture`/`srcset` как безопасная декларация для будущего сайта; batch очередь, отмена/повтор и понятные ошибки. Приоритет — корректные размеры и отсутствие утечек object URL / неконтролируемой памяти. Подготовить import/export metadata и пере-привязку файлов по digest; если offline session не может долговременно хранить blobs, явно показать это ограничение.

### 4. Галереи, слайдеры, иконки, видео-конфигурация

Добавить интерактивный редактор и превью минимум трёх композиций медиа: responsive grid, masonry-like layout, carousel на CSS scroll-snap с клавиатурой/доступностью, без обязательного тяжёлого runtime. Локальная библиотека небольшого набора СВОИХ безопасных пиктограмм (только строго разрешённые именованные токены, не произвольный SVG). Конфигуратор безопасного видео-постера/размеров/embed-адреса с явной allowlist провайдеров либо безопасной ссылкой без сетевого просмотра. Нельзя записывать сторонний JavaScript или придумывать CMS-поля, которые она уже якобы поддерживает.

### 5. Каталог эффектов и motion design

Визуальное превью безопасных motion пресетов (fade/slide/scale/reveal, последовательное появление, hover/active/focus, прочие уместные варианты). Контроль duration/delay/easing/амплитуды и мобильного поведения — со строгими диапазонами и enums. Генерация компактного детерминированного CSS для **реально использованных** пресетов, `prefers-reduced-motion: reduce`, управляемая focus-видимость, отсутствие мерцания/бесконечных циклов. Поведение scroll reveal, если нуждается в JS, сделать только как явно опциональную preview-функцию: существующий static exporter и release auditor запрещают произвольный активный JS на публичном сайте, поэтому публичный CSS должен иметь корректный fallback без JS.

### 6. Чистый контракт импорта в нашу CMS

Подготовить документированный **аддитивный, versioned, closed-schema** output contract `media-motion-bundle-v1`: метаданные файлов/variants, реальные SHA256, размеры, alt/caption/focal, gallery configs, icon tokens, motion configs и обоснованный CSS; JSON валидатор и экспорт бинарных файлов. НЕ изменяй действующий Stage3 `site-v1` или PHP API: подготовь чёткую таблицу сопоставления с текущими `site.assets`, существующими полями компонентов и ограничениями. Несовместимые будущие поля отметить `integration_required`, не «прибивать» их к работающему контракту скрыто. Главный после ревью сам подключит адаптеры к SDK/Studio/Server.

### 7. UI и готовность к ручной проверке

Работающий красивый цельный экран с нормальной мобильной/планшетной адаптацией и понятным пользовательским потоком **импорт изображения → редактирование → адаптивные версии → галерея/анимация → экспорт результата**. Реальные функции редактирования и предпросмотра, без декоративных неработающих кнопок. Дать несколько встроенных безопасных демо-состояний, подписанных как примеры, не как выдуманные факты о клиенте. Сохранение/загрузка проекта JSON и Undo/Redo для метаданных, где возможно.

### 8. Проверки по делу, а не лаборатория ради лаборатории

Одни сквозные Node smoke/contract проверки для плохих путей/типов/диапазонов/JSON и реального экспорта плюс один browser Chromium smoke для рабочего сценария (используй доступные pinned инструменты репозитория READ-ONLY, если доступны). Проверить три viewport, reduced-motion, операции batch и реальное скачивание хотя бы одной конвертированной картинки. **Не добавлять npm/сетевых зависимостей, новые workflows и сотни повторных тестов.** При обнаружении ограничений честно занести их в README.

## Definition of Done

- Пользователь может автономно открыть инструмент, добавить свои PNG/JPEG/WebP, увидеть **реально** изменённые output bytes, собрать галерею и выбрать анимацию; проект JSON и бинарный результат экспортируются.
- Metadata/validators/export имеют определённый versioned contract, опубликованный внутри subtree, с безопасными примерами и инструкцией интегратора.
- Ни один изменённый файл не выходит из `stage3/media-motion/`; нет npm install, CDN, API к реальным хостам, секретов, изменений главного редактора/серверной CMS.
- Нет лжи о «Stage 7 accepted»: это независимый Stage7-related development delivery. Stage 0/1 приняты, Stage2 NO-GO #5–#9, Stage3+ официально не приняты, 0/135.
