## Готовые функции, которые нужно сохранить

- Approved SEO Blueprint, интеграция с запечатанным Approved Site v2, owner-published Site v1, реальные PHP local technical checks, официальный static export, public-only ZIP и verified host package.
- Source-bound Lead Integration Relay, приватный SEO Operator Workspace и `run-first-site-integration.cjs` с режимами `local`, `public`, `public-capture`, `search`.
- `public-capture` после ручного деплоя ведущим делает только разрешённые публичные HTTPS GET с pinned DNS/TLS и SHA256 медиа, затем проверяет настоящий релиз и готовит приватный browser/form checklist. **Никаких POST, деплоя и автоматического GO.**
- `first-site-candidate-preflight.cjs`: версия/revision/manifest/ZIP до сетевого запроса.
- `first-site-session-source-pin.cjs`: снимок хешей owner JSON, исходного PHP отчёта/bundle, static upload и ZIP до/после многоэтапного запуска, с отказом при подмене исходников.
- `first-site-live-acceptance.cjs`: не просто общее число форм, а точная карта `seo-report/bundle.json -> localPhpForms.pages[]`; требует отдельные операторские свидетельства реальных POST **по каждому опубликованному маршруту**; пропуски видны в приватном интерфейсе.
- GSC Search Performance, Search Indexing и History с реальными owner-provided evidence, CMS action packets без CMS writes.

## Строгие правила работы

1. **Большие функциональные заходы, ориентир ~30 минут содержательной работы.** Пользователь неоднократно просил не завершать через 10 минут или после одной мелкой задачи. Решай несколько совместимых практически полезных задач за заход и затем отчитывайся.
2. **Сначала доводим работающую CMS и первый настоящий сайт**, потом мелкая полировка. Не раздувай абстрактные отчёты, тестирование ради тестирования и формальности.
3. Тесты — только важные быстрые smoke/синтаксис и затем реальный клиентский PHP/HTTPS/browser через ведущего. В SEO-ветке пока нет GitHub Actions; изолированные V8 smokes были успешны, но **Node CI, реальный PHP сайт и production POST не подтверждены**.
4. **Пиши и коммить только в `feature/site-seo-engine` и `stage3/seo-engine/**`.** Никаких PR, merge, deploy, GitHub Actions, изменений PHP/CMS/Studio/SDK/root и коммитов приватных данных. Только главный чат интегрирует наши изменения и принимает решения по хостингу/публикации.
5. Перед новым функциональным блоком проверь, что он не дублирует существующий код. При обнаружении ошибки/несоответствия с настоящим форматом данных исправь её практическим коммитом, а не очередной таблицей.
6. Пользователь не должен вручную давать уже известные условия. Смотри код и документы и делай самостоятельно. После большого блока обнови документы, проверь текущий HEAD и Compare, сообщи короткую передачу.

## Следующий приоритет

Первый реальный клиентский SEO rollout: ведущий должен интегрировать весь SEO subtree в свой checkout, проверить Node smoke, owner-authenticated published Site v1/sourceRevision, sealed Approved Site v2, официальный PHP/static export, получить реальный localhost, затем собственноручно развернуть только одобренный PUBLIC ZIP.
