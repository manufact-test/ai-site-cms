## D1. Compiler & design tokens: работающая основа (цель 1/7)

- Versioned `manufact-design-factory-v1`: themes/recipes/kits + строгий validator, миграция допустимых версий и безопасная сериализация.
- Детерминированный compiler: отраслевой бриф + реальные owner facts → `manufact-ai-site-v1` через фактический registry; ошибки/отсутствующие поля явно показаны; контроль стабильных ID, внутренних URL, SEO, navigation, alt; порядок секций не плавает.
- Поддержка полностью пустого дизайн-брифа, RU/EN, безопасные дефолты и optional реальное описание услуг владельца.
- CLI create/validate/inspect/export, Node smoke, рабочие примеры. Не трогать `stage3/sdk/`.
- **DoD:** сгенерированный сайт проходит действующий `stage3/sdk/contract.cjs validateSite` и round-trip JSON без неизвестных свойств; два разных брифа дают содержательно разную композицию.

## D2. Visual system: набор профессиональных тем (цель 2/7)

- **Не менее 12 самостоятельных дизайнерских направлений** с палитрами, контрастом, шрифт-иерархией, вертикальным ритмом, layout, правилами мобильной композиции, кнопками/карточками/навигацией, focus/hover/disabled и CTA. Темы не должны отличаться только hex цветом.
- Разделяй `CMS-expressible` (в рамках реальных `theme`, `appearance` enums) от `integration_required` для будущих расширений. Не утверждай ложную pixel-parity с PHP renderer.
- Закрытый каталог токенов, подсчёт контраста и локальные first-party CSS, автоматическая проверка границ CSS vars и загружаемых ресурсов.
- **DoD:** любой kit можно визуально переключить между темами, результат на трёх ширинах не распадается, настройки сохраняются и экспортируются.

## D3. Section architecture: существенная композиционная библиотека (цель 3/7)

- **30+ профессионально спроектированных вариантов секций/композиций**, включая разные hero/layout/benefits/services/process/team/portfolio/pricing/testimonials/FAQ/contact/CTA/gallery и доверительные блоки.
- Не создавать фиктивные `site-v1` компоненты. Если нужны новые, подготовить в `stage3/design-factory/proposals/` **спецификацию** manifest и PHP/Studio adapter mapping, но не писать туда, где работает главный.
- У каждой композиции: responsive desktop/tablet/mobile, редакторское описание, data requirements, доступность, безопасный fallback, какие утверждения нельзя выдумывать.
- **DoD:** действительно разные layouts проверены в standalone showcase, а экспортируемые поддерживаемые секции прошли реальный contract validator.

## D4. Multi-page sector kits: большой полноценный каталог (цель 4/7)

- **12+ содержательных отраслевых site kits**: digital agency, local professional services, manufacturing/B2B, SaaS, logistics, architecture, education, personal portfolio, restaurant information (без стороннего booking), repair/home services, nonprofit, consulting. Допускается более точная отрасль из исходных требований, не подставляй клиентские бренды.
- Каждый kit — **минимум 4 полноценные страницы**, осмысленная навигация, hero/ключевые блоки/сервисы/FAQ/контакты, отдельное SEO title/description и доступные CTA. Минимум 3 разных по структуре базовых archetypes, не копируй один JSON 12 раз.
- Контент профессиональный, **нейтральный, без фальшивых цен, лет опыта, отзывов, гарантий, имен компаний, лицензий и контактных данных**. Незаполненное обозначается как требующее ввода владельца; пропуски отражаются в checklist.
- Минимум 4 кита с аккуратными RU/EN примерами без ложных данных; остальные RU допустимы, если документация фиксирует покрытие.
- **DoD:** все 12+ экспортируются в действующий `site-v1` и проходят строгую валидацию и контроль ссылок; каталог реально виден в браузере.

## D5. Browser Design Factory: реальный инструмент, не мокап (цель 5/7)

- Полностью локальный HTML/CSS/JS UI: каталог 12+ kits, фильтр отраслей, предпросмотр страниц и секций, переключение 12+ themes, настройки бренда/контента, desktop/tablet/mobile, Undo/Redo, проектный JSON import/export.
- Поддержать реальную генерацию и скачивание `site-v1` по выбранному киту, theme, brief и pages. У каждого элемента UI есть функция; error states, клавиатурный доступ, mobile удобство.
- Предпросмотр не должен выполнять недоверенный HTML/JS, не должен выдавать визуально неподдерживаемые свойства как «уже готово в CMS».
- Никаких CDN/font-hosting/external API/host calls; browser без backend.
- **DoD:** пользователь от выбора бизнеса до валидного site JSON проходит реальный Chromium E2E на трёх viewports; не менее 4 meaningful customization.

## D6. Integration bridge: передаваемая главному готовая подсистема (цель 6/7)

- Подготовить безопасный versioned exporter/importer contract, `site-v1` validator parity matrix с ссылками на реальные source файлы.
- Таблица `supported / integration_required / blocked` для секций, стилей, SEO, media, responsive, links, формы (formCollector остаётся отдельной серверной конфигурацией), будущих анимаций.
- Прямое подключение **без модификации ядра**: валидный site JSON для нынешнего импортера, stable IDs, no broken local routes, explicit publish gate, no new unexplained props; отдельный semantically rich design-spec manifest для адаптеров.
- Reusable samples + сквозной Node контрактный smoke + один Chromium browse→edit→export smoke. Никаких десятков параллельных CI лабораторий.
- **DoD:** главный может забрать из твоей папки валидный набор файлов/JSON и импортировать supported subset; состав будущих адаптеров точно указан без допущений.
