## Главный смысл новой организации

**Это НЕ разовое задание и НЕ поручение «сделать один инструмент».** Тебе выделено **постоянное, достаточно большое направление CMS — фабрика профессионального дизайна и отраслевых сайтов**. Оно содержит **7 крупных программных результатов** (см. `ROADMAP.md`) и рассчитано на многократные полноценные заходы. Окончание одного результата НЕ означает завершения твоей миссии и НЕ требует нового технического задания от главного чата.

Второй чат развивает это направление непрерывно в рамках последовательных пользовательских сообщений: после каждого успешного этапа сам переходи к следующему по `ROADMAP.md`, при обращении владельца «продолжаем» бери следующий крупный блок, **не спрашивай, что делать дальше**. Обычный чат не выполняет задачи асинхронно между сообщениями; это дорожная карта для следующих сообщений, а не обещание фоновой работы.

Никаких заданий «на 20 минут», искусственного растягивания времени и бесконечных тестов. Критерий объёма — **целиком законченные пользовательские сценарии и десятки качественных производственных артефактов**, а не число минут, строчек или коммитов. Не сокращай объём программы самостоятельно до MVP/одного компонента.

## Продуктовая цель

Создать отдельную, **по-настоящему работающую** Design Factory, которая формирует профессионально выглядящие многостраничные сайты из выбранного типа бизнеса, дизайн-направления и фактических данных заказчика, при этом:

1. Сгенерированные документы **валидны для реально зарегистрированного Stage3 `manufact-ai-site-v1`**, а не для придуманного формата, и могут быть переданы главному без ручного переписывания сотен полей.
2. Дизайн различается **композицией, сеткой, ритмом, иерархией, взаимодействием и содержанием**, а не одной лишь заменой цветов.
3. Есть реальный standalone **browser Studio/каталог** для выбора шаблонов, переключения тем, предпросмотра desktop/tablet/mobile и экспорта; «кнопки для красоты» недопустимы.
4. Для возможностей, которых существующий `site-v1`, `stage3/components/` и PHP renderer ещё **не поддерживают**, есть отдельные versioned предложения/адаптеры, **не подмена фактов и не скрытые расширения рабочего контракта**.
5. Профессиональный дизайн не достигается выдуманными фактами: ни ложных отзывов, ни вымышленных цифр/клиентов/сертификатов, ни чужих изображений/логотипов.
6. Всё работает offline, без внешних AI API и CDN. В будущем главный подключит генерацию на основе ИИ, но твой пакет обязан работать детерминированно уже сейчас.

## Технические контракты

- Совместимость — текущий **первичный** контракт `manufact-ai-site-v1` + реально зарегистрированные manifest JSON. Выдели собственный **дополнительный** формат `manufact-design-factory-v1` для рецептов, тем и схем layout. Он НЕ заменяет `site-v1`; экспорт в CMS должен пройти текущий `sdk.validateSite()`.
- **Разделяй два результата:** (A) сайт со 100% совместимостью на поддерживаемых свойствах CMS; (B) отдельная **integration_required** спецификация для новых макетов/анимаций/сеток. Нельзя обещать, что CMS повторит CSS-превью, если PHP renderer не поддерживает layout.
- Поддержи manual design brief и **без макета** (AI chooses safe default), доступный простой контент-бриф; не генерируй персональные сведения/телефоны/отзывы как реальные. Не раскрывай секреты и ключи.
- Основной workflow: **выбрать отрасль → выбрать концепцию/тему → заполнить реальные данные → посмотреть 3 устройства → поменять тему/разделы → получить валидный `site-v1` JSON + предпросмотр**.
- Все интерактивные элементы HTML работают без недоверенного `innerHTML` или dynamic code. Browser preview не должен выполнять чужой HTML/JS.
- Поддержка i18n RU/EN на уровне данных/профессиональных текстов как минимум для 4 типовых пакетов; содержание семантическое, без лживых обещаний, контактные данные как явные placeholders.
