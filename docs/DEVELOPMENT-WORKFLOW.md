# Правила разработки AI Site CMS v2.0 · 27.10.2026
**Важнее любого прежнего ускорительного/тестового протокола:** [MASTER-TZ.md](MASTER-TZ.md). Никаких целей за пределами мастер-ТЗ без прямого одобрения владельца.

1. Один ведущий разработчик/интегратор. Вторая ветка строго \`stage3/seo-engine/**\`, и только после прочтения \`handoffs/parallel/SEO-ENGINE-v2-ASSIGNMENT.md\`.
2. Сначала работающий путь **три картинки + описание клиенту + внутренняя переносимая спецификация + явное утверждение → один настоящий сайт → лёгкая CMS → SEO и повторяемые элементы**. Не программировать прототипы как сайты.
3. Один рабочий заход — **большая функциональная вертикаль**, а не тесты ради тестов. Использовать уже готовые SDK/Studio/PHP/renderer/формы/интеграции. Нет новой реализации если подходит старая.
4. Проверки: syntax/safe validation/предсуществующий CI + только один-два релевантных smoke для нового пользовательского пути; серьёзные security/recovery gates сохраняются. Не добавлять бессмысленные mock suites или десятки отрицательных проверок, когда функция ещё не реализована.
5. Начинать review с настоящего пользовательского интерфейса, не объявлять «готово» до того как владелец посмотрит законченный путь. Его будущие правки ожидаемы. Не ждать визуального совершенства на каждом промежуточном коммите.
6. Коммитить большие законченные логические блоки с коротким summary: сделали, сценарий, CI, что осталось. Документы обновлять при существенном изменении и handoff, не на каждом шаге.
7. Прямой запрет: создание новых готовых тем/сайтов в Design Factory, лишние сервисы, AI чат в админке, CRM, параллельные UI и избыточные export labs без реального пользовательского основания.
8. Удаление кода: собрать точные импорты/маршруты/CI/публикационный комплект; только доказанный ненужный код удалить, проверить результат. Одна папка *в Git* не равно runtime нагрузка. В Design Factory branch не трогать нужные сторонние файлы и ничего не вливать.
9. Без main merge, Hostinger/prod writes, shared databases и CELIKOM live. Owner GO для операций с риском и любых новых расходов. Не использовать фразу «полная приёмка» по зелёному CI.
