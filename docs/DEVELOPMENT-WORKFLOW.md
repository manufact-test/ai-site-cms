# AI Site CMS — постоянный протокол разработки

**Последнее подтверждение владельцем: 18.10.2026 (v1.41).** Применять во всех следующих чатах. Это **обязательные рабочие правила**, а не рекомендация и не разовая задача.

## 1. Размер задач — крупные объединённые пакеты

По команде владельца «продолжаем» ассистент сам берёт **несколько взаимосвязанных крупных задач**, достаточных для ощутимого продвижения целого технического процесса/модуля за один заход. Не завершать очередной рабочий круг после одного мелкого теста или небольшого метода. Не запрашивать мелких решений по стеку/порядку работы: выбор технологии и инженерный подход делегированы ассистенту. Держаться утверждённого 18-этапного Master/Roadmap и не пропускать приёмку этапов.

## 2. Документация — ТОЛЬКО по прямому запросу при переходе в новый чат

**ВЛАДЕЛЕЦ ЗАПРЕТИЛ обновлять документы после обычных задач и после больших технических блоков по собственной инициативе.** Нельзя в конце каждого пакета переписывать docs/NEXT-CHAT.md, PROJECT-STATUS.json, ROADMAP, отчёты или версии только ради «сохраниться». **Даже «очень большой milestone» не является исключением.** Исключение — владелец сам явно пишет, что переходит в другой чат, и просит сохранить/обновить документы; тогда все документы обновляются **однократно в конце этого чата**, после финальной проверки, со ссылками на реальные commit/CI. Такой запрос сделан при передаче v1.41.

Код, тесты, CI workflow и сам GitHub **обновлять при необходимости** — запрет относится только к постоянному переписыванию проектных документов/статусов в обычных циклах разработки.

## 3. Инженерная проверка — общая для пакета

Предпочитать один общий финальный CI для логически законченного блока и меньше промежуточных запусков/коммитов, не замедлять работу избыточными повторами. При обнаружении реальных ошибок исправлять и повторять до зелёного конечного HEAD. При этом **не убирать важные тесты безопасности, не выдавать CI-only за production, не скрывать незакрытые проблемы**. Итоговый ответ: кратко что сделано, изменившаяся реальная польза, подтверждённые GitHub Actions, SHA, этап/границы.

До Stage2 acceptance не начинать Stage3. **Hostinger запрещён даже read-only до отдельного явного разрешения владельца.** Не менять CELIKOM/клиентские сайты, не merge `research/stage1-editor-comparison`. Полный выпуск только после 135/135 обязательных требований, нет ускоренного урезанного MVP.
