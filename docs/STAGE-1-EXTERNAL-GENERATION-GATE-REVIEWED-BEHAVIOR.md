## Block A: immutable-in-this-commit paired source+manifest evidence gate prototype

Research file: `external-generator-contract-gate.cjs`; standalone sources `fixtures/cedar-lab-standalone.html` and `fixtures/tide-atlas-standalone.html`.

- Introduced a versioned test protocol representing **three separate obligations**: generated site source HTML/CSS/JS, generated editable field manifest, and a separately defined reviewer oracle of required source fields/semantics. A model's claimed provider/name/identity inside its own manifest is **not independently verifiable**; the checker **never** marks external model generation proven based on self-assertion.
- **28 manually defined required obligations** across two independent *site shapes* (Cedar Lab 15; Tide Atlas 13), **31 checks**, **17 negative gate refusals**, **14 explicit source/manifest mutants**. Two correlated omissions (missing from BOTH input HTML and candidate manifest) are caught because the reviewer oracle still demands them; stable-ID joint renames also fail pending explicit review.
- Checks cover specific text, hash links, responsive layout/gradient/animation signals, media attributes, HTML disclosure/form/dialog semantics, SEO metadata and presence of original event handlers. Type mismatch, duplicate fields, fake fields, omitted declarations, missing site element, dangerous link and invalid dialog behavior cause refusals.
- **All 28 known oracle obligations do NOT equal universal property detection.** Seven unreviewed capability categories in each fixture remain quarantined, even when all field names are present. Regex-based CSS tests cannot prove arbitrary style behavior. The source and oracle were authored by the same research assistant. **No external second-model output was produced, no hidden genuinely blind grader exists and no independent model provenance was confirmed.**
- Baseline protocol fingerprint, for a future strict external provenance chain: `50218db02cb47af4825d9e10b9d7970ebdd2c15b56aa034eb4190f6e147b354c` (SHA-256 of this version's deterministic protocol JSON). This is a reproducibility marker, **not** a signature, immutable secure commitment, or external model-attestation service. Later independent trials must lock and separately control the hidden evaluation and unseen challenge prompts.

## Block B: original rich source + reviewed behavior in real Chromium opaque sandbox

Research file: `reviewed-rich-behavior-browser.cjs`, reuses the previously tested Cedar Lab site.

- **26 successful Chromium assertions**, including one explicitly counted denied/replay message and separately checked invalid commands: stage1 trust adapter parses HTML, strips original executable `script` elements and inline event-handler attributes, removes dangerous URL scheme in fixture, injects ONLY a reviewed controlled inline script using a fresh CSP nonce, and leaves the sandbox opaque with `sandbox="allow-scripts"` but **without `allow-forms` or `allow-same-origin`**.
- Reviewed field commands require exact channel/token, parent origin/source, monotonic sequence and exact typed bindings: `menuEnabled`, `formPreviewEnabled`, `ctaHref` (in-page fragment only). A signed publisher or raw HTML never gets arbitrary JS/network/file privileges. Navigation menu `aria-expanded` now toggles from trusted logic despite source JS being removed; owner updates are applied without running original handlers. CSS gradient and HTML visible title remain retained.
- Native sandbox may suppress HTML submit events without `allow-forms`; test uncovered this issue. Resolved with an **explicit reviewed submit-button click listener** that emits only a local preview acknowledgement. **Zero real form requests and zero external network requests**. Tested stale sequence replay, malformed signed-looking values/fields, unsafe `javascript:` href, wrong token and unexpected fields; original script sentinel remains undefined.
- This is NOT general-purpose HTML sanitizer, complete production CSP/permissions implementation, an authentication mechanism, independently generated custom behavior, real form backend or faithful arbitrary original JavaScript execution. The menu/form behavior is a **manually code-reviewed replacement for known stable IDs**, not preservation of unknown JS; future feature review/registration must be explicit.

## Decision implications, not a stack approval

The data favors explicit model-generated contracts, mandatory oracle-guided coverage, reviewed behavior registries and strong sandbox boundaries irrespective of the editor/foundation. Native HTML read-only behavior and separately trusted action reconstitution can be composed, but only for known capabilities. It does not choose PHP-first, React/Next schema editor or a Puck/Craft selective field engine. All A/B/C remain owner decisions after Stage1 evidence.

**Non-negotiable next work:** obtain an actually independent/blinded second model output and **independently model-produced** manifest from locked never-seen prompts with an evaluator withheld from the generator; test multiple substantially different designs, compute precision/recall and auto-editability coverage, and safely review unsupported CSS/JS/actions. Other outstanding blockers: actual immutable external trust witness and key lifecycle, security/authorization, full original CSS/JS/media/SEO and responsive behavior parity, production-grade storage/backup and explicitly owner-authorized read-only hosting smoke. No live Hostinger/CELIKOM access.
