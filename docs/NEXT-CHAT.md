## Готовый старт следующего чата

Продолжаем проект **AI Site CMS** в отдельном репозитории `manufact-test/ai-site-cms` (ветка `main`) — систему управления сайтами, которые изначально создаёт ИИ. Не строим ручной конструктор страниц вроде Elementor; ИИ создаёт вёрстку и одновременно обязуется регистрировать компоненты, свойства, исходные значения и адаптив. Владелец редактирует отдельный выбранный блок: слева предпросмотр, справа свойства, остальные тяжёлые секции не загружаются. Видны только реально используемые на конкретном сайте настройки; все ручные правки переживают обновления кода.

**12 частей опросника завершены, 193 ответа:** 135 «Обязательно», 42 «Желательно», 16 «Не нужно». См. `docs/REQUIREMENTS.md` и Excel `requirements/CMS_REQUIREMENTS_REGISTER_v0.1.xlsx`. Дополнительный обязательный пункт №119: даже при просьбе «сделай сайт на свой вкус» ИИ создаёт полную схему управления.

**Приоритет:** все 135 обязательных — к первой ПОЛНОЙ версии CMS; **никакого публичного MVP**. Внутреннее поэтапное тестирование допускается. Никаких пробных установок на живой CELIKOM до полной приёмки CMS.

**Документы:** `docs/MASTER-TZ.md`, `docs/REQUIREMENTS.md`, `docs/OPEN-QUESTIONS.md`, `docs/ROADMAP.md`, `docs/ARCHITECTURE.md`, `docs/AI-SITE-CONTRACT.md`, `docs/FOUNDATIONS.md`, `docs/ACCEPTANCE.md` и этот `NEXT-CHAT.md`.

**Зависимости:** целевая платформа должна работать на обычном shared hosting и поддерживать HTML/CSS/JS, PHP, React/Next (при SSR возможны другие runtime). Не нужны WordPress, универсальный импорт существующих сайтов, редактор произвольного CSS или ручная сборка новых страниц. У каждого сайта — своя установка и данные.

**Сейчас:** уточнить вопросы из `docs/OPEN-QUESTIONS.md`, согласовать архитектуру и выбрать техническую базу. **Без написания кода до утверждения ТЗ и архитектурных решений.**

**ОТДЕЛЬНО:** сайт CELIKOM + его небольшая админка находятся в `manufact-test/nomusic`. Не трогать этот репозиторий, не размещать здесь его исходники, не сливать PR и не запускать CMS на его продакшене до полной готовности.

**При просьбе «обновить файл для нового чата»:** синхронизировать состояние GitHub, дату, принятые решения, закрытые/открытые требования, архитектурные блокеры, следующий конкретный шаг; старую актуальную задачу заменить, историю решений сохранить. Не удалять значимые решения, не подменять «желательно» на «обязательно», не выдумывать приёмку. Выдать обновлённый checkpoint.
