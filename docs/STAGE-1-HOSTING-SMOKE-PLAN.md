# AI Site CMS — этап 1: безопасный план проверки текущего PHP shared-hosting

**Статус:** план, НЕ исполнен на реальном хостинге · 17.10.2026 · checkpoint v1.12.
**Правило:** сохранять существующий тариф, рабочие сайты, PHP-настройки и конфигурацию сервера; не разворачивать исследовательский publisher как публичный сервис.

## Цель и факты

Исследовательская среда GitHub Actions использует PHP 8.3.6 CLI и Opis JSON Schema 2.6.0 с Node лишь при сборке/тестах. Реальная версия PHP и ограничения имеющегося shared-hosting **не известны**. Совместимость нельзя вывести из локального PASS. Не использовать реальный CELIKOM либо рабочие сайты для этого эксперимента.

## Безопасный порядок

**Шаг A — read-only, без файлов на хостинге.** С разрешённого аккаунта панели снять в приватный отчёт (не в публичный GitHub): точная версия PHP, handler (FPM/CGI, если показывается), доступные extensions (JSON, mbstring/intl при наличии, fileinfo, openssl, PDO/MySQL, curl, sodium, zip), версия БД, доступность SSL, web server / rewrite controls, текущие memory_limit, max_execution_time, post_max_size, upload_max_filesize, max_input_vars; доступность логов ошибок/HTTP, cron, CLI PHP/SSH, backup/export/restore, path вне document root, запреты на запись / chroot, ограничение количества файлов/inodes, права на файловое хранилище. Отметить неизвестное отдельно. Секреты и абсолютные приватные пути не коммитить.

**Шаг B — только по отдельному согласованию изолированной директории.** Создать случайный каталог на согласованном тестовом домене/поддомене **без подключения к продуктивным сайтам**, доступный только авторизованному тестировщику (например, access control на уровне хостинга). Внутри временный неинтерактивный PHP probe с одноразовым токеном; без `phpinfo()` на общедоступном URL, без вывода credentials, document root, environment variables, конфигов БД или иной инфраструктурной информации. После прочтения — удалить. Не переключать PHP-версию сайта и не менять глобальную конфигурацию.

**Шаг C — ограниченный функциональный smoke, если A/B допустимы.** Проверить GET/HEAD/405 и правильные content types/headers; доступность временной записи в приватном каталоге, flock, rename, 2 параллельных тестовых процесса при разрешённом CLI, чтение/удаление файла, недоступность приватного каталога через HTTP; JSON/Unicode/Opis на той же схеме и в той же PHP web SAPI; отсутствие требований к Node runtime на публичном сайте. Проверить поведение при отсутствии поддержки расширений, без неограниченной нагрузки. Не трогать реальные данные, БД, системные rewrite и клиентские домены.

**Шаг D — безопасность и отчёт.** Проверка отклонения прямых HTTP попыток чтения приватных файлов (403/404); no-cache для чувствительного ресурса; журналы без секретов; порядок бэкапа и восстановления тестовых данных; удаление временного каталога. Зафиксировать фактические версии, тестовые команды, HTTP-ответы, ограничения и разрешённый охват. Отдельно учесть, что PHP CLI и PHP HTTP SAPI могут различаться.

## Запреты и гейты

- Нет общего доступа/изолированного разрешённого пространства → **только шаг A**, отметить блокер, не подменять «Hostinger проверен» результатом GitHub CI.
- Тариф, PHP handler, настройки рабочего домена, БД, cron, глобальные правила, деплой и backups не менять ради эксперимента.
- Два reader-validator (CLI Opis и отдельный PHP reader) по-прежнему могут расходиться на иных схемах; smoke не утверждает production durability/backup, XSS/CSP/CSRF/RBAC, crash safety, конкурентность, масштабируемость.
- Next.js **static export** — готовый HTML-артефакт; **Next.js SSR** и runtime Node не проверены и не обещаются на PHP-only shared hosting.
- Любой найденный пробел документировать в [OPEN-QUESTIONS.md](OPEN-QUESTIONS.md) и [STAGE-1-TEST-LOG.md](STAGE-1-TEST-LOG.md), не выбирать архитектуру автоматически.
