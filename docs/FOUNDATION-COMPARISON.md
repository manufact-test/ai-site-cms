## 1. Уточнённая стратегия владельца

AI Site CMS — **внутренняя разработка команды** для сопровождения админок клиентских сайтов; не планируется продавать готовую CMS. Клиенты могут пользоваться админкой по сети. Отдельно зафиксировано в [MASTER-TZ.md](MASTER-TZ.md) §1.4.

**Приоритет: переиспользовать готовый качественный код, даже существенную часть библиотеки с собственной адаптацией**; бессмысленной «переписи для изменения процента» не делать. Если копируется фрагмент или модуль, его исходная лицензия сохраняет действие; для permissive-проектов проверяем LICENSE/NOTICE и сохраняем требуемые служебные уведомления. Сетевой доступ и передача программы клиенту не всегда эквивалентны только внутреннему использованию: GPL/AGPL или коммерчески ограниченные компоненты — только после отдельного согласования. **Ни автора, ни чужие бренды в интерфейсе показывать по умолчанию не требуется.**

**Инфраструктурное ограничение:** на данном этапе **только текущий обычный PHP shared hosting**. Отдельный Node runtime для работы CMS не вводим без нового решения. Node для локальной/CI-сборки JS допустим; статическая админка в браузере + PHP API не требует рабочего Node-сервера. Next.js SSR остаётся отдельным runtime/хостингом сайта, его нельзя объявлять работающим на PHP-only хостинге.

## 3. Оценка направлений — не выбор

| Проверяемая архитектура | Что переиспользуем | Что своё | Как проверять |
|---|---|---|---|
| **A. Модульное PHP API + schema-driven controls** | Slim/Symfony компоненты, JSON Forms **или** RJSF, schema validator, UI primitives | AI manifest, selectors, bindings, responsive/token engine, drafts/pub, revisions | Наиболее экономный на хостинге **по гипотезе**, но много backend glue |
| **B. Адаптированный Puck + PHP backend** | Puck fields, preview, editor shell; PHP core separately | Полное исключение DnD, независимость от React-сайтов, manifest translation, publish | Проверить, возможно ли вообще эффективно использовать Puck без опоры на его собственный page data model |
| **C. Winter CMS + отдельный block-editor** | PHP auth, БД, permissions, admin API, plugin features | AI contract, изолированный preview, кросс-стек адаптеры, migrations | Проверить, не сложнее ли retrofit ядра, чем модульный путь |
| **D. GrapesJS только компонентами UI** | Style Manager, trait controls, selection механизмы | Сохранение в свой schema data model, фильтрация builder-функций | Отделимость UI от внутреннего DOM source of truth |

**Исследовательское предпочтение (не решение):** сначала A, в качестве сравнения B и C; D — точечный источник готового UX-кода, а не готовое ядро.

**Ограничение стенда:** Node и PHP CLI в рабочем окружении инструментов доступны, но настоящие npm-пакеты для сравнения из сети в этом проходе не устанавливались; никаких runtime/lighthouse/performance результатов не заявлено.

### 3.2. Проверка manifest-зависимостей и PHP/runtime границ

Открыты `composer.json`/ `package.json` именно исходников соответствующих проектов, **не** сделана установка. Результаты для предварительного фильтра:

| Пакет | Проверенное объявление | Последствие |
|---|---|---|
| [Slim](https://github.com/slimphp/Slim/blob/4.x/composer.json) | PHP ~7.4 / ~8.0–~8.5, `ext-json`, 9 прямых composer requires | Возможен PHP-only API на современных версиях PHP; нужно проверить нужную host PHP + webserver rewrite/session/storage |
| [Winter](https://github.com/wintercms/winter/blob/develop/composer.json) | PHP >=8.1, 7 top-level composer requires | PHP-only runtime по ядру, но фактические установки/пакеты/шаблоны/виджеты могут потребовать больше; не считать приложение «из 7 зависимостей» |
| [Opis JSON Schema](https://github.com/opis/json-schema/blob/master/composer.json) | PHP ^7.4 или ^8.0, `ext-json`, 4 требует | Возможен server-side validator; поддержку конкретных draft/форматов/злонамеренных ссылок в схеме проверять отдельно |
| [Symfony HttpKernel](https://github.com/symfony/http-kernel/blob/7.4/composer.json) и [Routing](https://github.com/symfony/routing/blob/7.4/composer.json) | PHP >=8.2 для выбранной ветки | Если PHP на текущем hosting ниже 8.2 — это блокер для этих версий; **не** предполагать версию тарифа по локальной PHP CLI |
| [JSON Forms React](https://github.com/eclipsesource/jsonforms/blob/master/packages/react/package.json) | 1 direct dependency + peer `@jsonforms/core`, React | Следует считать полный набор packages/renderer deps, не только оболочку; текущая ветка `master` может содержать alpha peer, поэтому фиксировать **стабильный релиз**, а не master |
| [RJSF core](https://github.com/rjsf-team/react-jsonschema-form/blob/main/packages/core/package.json) | 1 direct dependency + peer `@rjsf/utils`, React>=18, Node>=20 в `engines` | Проверить сборку в CI отдельно; готовый статический UI может работать на PHP backend без Node runtime, но это надо доказать сборкой |
| [Puck core](https://github.com/puckeditor/puck/blob/main/packages/core/package.json) | 36 direct dependencies, React 18/19, Node>=20 для toolchain | Нельзя считать модуль независимым; нужно замерить фактический статический bundle и проверить работу вне React-сайта |

**Контракт не равен JSON Schema 1:1.** У AI Site CMS есть собственные `content/style/behavior`, responsive inheritance, stable IDs, defaults и schema versions. Даже если RJSF/JSON Forms создают контролы из JSON Schema, понадобится детерминированное преобразование **manifest → поля**, а обратное изменение должно адресно менять published config/preview, **не** писать CSS/JS и не перезаписывать авторские defaults. UI `onChange` нужен для живого предпросмотра, но **не означает автосохранение** (№132 «Не нужно»). Сервер повторно проверяет все значения.

**Доказать позднее:** фактическую PHP-версию и расширения существующего хостинга, возможность установки архивом без Composer на сервере, наличие rewrite/HTTPS, правильность cookie/CSRF, скорость и размер статической JS-панели, импорт ровно допустимых лицензированных зависимостей.

## 3.5. Nested responsive, shadow, animation, single preview — реальный Chromium PASS

17.10.2026: [GitHub Actions #39054829619](https://github.com/manufact-test/ai-site-cms/actions/runs/39054829619) успешно проверил **оригинальные Jedison и RJSF** с единой вложенной схемой Hero: \`responsive\` (desktop/tablet/mobile), \`shadow\` (x/y/blur/color), \`animation\` (enabled/duration/easing). Через реальный браузерный ввод у **обоих** desktop меняется \`64px → 58px\`, tablet \`48px\` и mobile \`36px\` сохраняются; blur \`10 → 18\`, duration \`400 → 650\`. Список из 50 metadata секций не вызывает создания дополнительных iframe; **ровно один** iframe подтверждает применение font-size \`58px\`; draft dirty не означает saved/published.

**Рамки:** задействованы стандартные вложенные поля, а **не кастомные field factories** для красивого CSS-интерфейса. В тестовом bridge есть \`postMessage("*")\` и фиксированный nonce — **не образец безопасного production-кода**. Не проверены настоящий сайт, Hostinger, CSS unit parsing, validators PHP/JSON Schema, тяжёлые секции, cookies/CSP/XSS, реальные timings/FPS/RAM, сохранение в БД. Исследовательский приоритет остаётся Jedison благодаря меньшему размеру предыдущего JS-entry, но **стек не утверждён**. Подробный честный протокол — [STAGE-1-TEST-LOG.md](STAGE-1-TEST-LOG.md) §8.

## 4. Честная матрица соответствия 135 обязательным ID

Здесь **не проценты реализации и не тестовые результаты**: категории — документальные гипотезы.
- **А** — виден пригодный модуль/примитив, но необходимы интеграция и доказательство работоспособности.
- **С** — обязательную функцию нужно проектировать у нас самостоятельно, используя при необходимости маленькие библиотеки.
- Ни один пункт не считается **«из коробки»** без работающего end-to-end теста на нашем сайте, поэтому для всех направлений «проверено готовым» = **0/135**.
- Таблица систематически рассматривает *направления* и подсистемы. **Тест 3: выполнение на текущем типе хостинга.** Установка PHP API и предварительно собранных assets без серверного Node и без VPS; конфиденциальные данные вне webroot, auth, cookies, логирование. Отдельно подтвердить возможность upload/update/restore, а не просто отдачу `index.php`.

**Тест 4: три типа сайта.** Одна схема параметров для HTML/CSS/JS, PHP, React/Next static (а SSR описать отдельным адаптером, не имитировать совместимость с PHP-only). Убедиться, что public pages работают, когда CMS выключена.

**Тест 5: размер/нагрузка.** Одинаковые условия для UI альтернатив; измерить загружаемый JS/CSS, время открытия и памяти только **одного** Hero (включая тяжёлый медиа), 50 секций только в метаиндексе. Замеры вести в фактических единицах, без придуманных KPI до утверждения.

**Тест 6: лицензии и цепочка поставки.** Взять только те подпакеты, которые реально нужны, проверить конкретный release/license/NOTICE/транзитивные зависимости (не только верхний repo LICENSE). Сведения сохранять в техническом `THIRD_PARTY_NOTICES` при включении кода; не в интерфейсе.
