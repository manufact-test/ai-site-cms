## New combined research block — the missing integration between v1.28 and PHP persistence

**Files (experiment branch only):** `research/stage1/rich-source-persistent-store.php`, `research/stage1/rich-source-persistent-test.cjs`; final step in `.github/workflows/stage1-editor-research.yml` mixed-site-trust job (pinned browser dependencies are present there).

**75 test assertions, 14 expected denied scenarios, 34 distinct PHP CLI process invocations**; a persisted draft and published page are rehydrated in fresh Node and **actual Chromium**, with original responsive CSS and approved owner overrides. A full complete source HTML/CSS/JS page is stored as **data** (not executable in PHP); restricted preview strips original scripts and event attributes and prevents network form requests. This is the original hand-authored Cedar Lab full-page source, **not** a separately generated second-model website.

- PHP CLI file journal persists the ORIGINAL HTML source text and four typed owner overrides (hero heading, in-page CTA fragment, img alt, bounded `--gutter` CSS token). A manually authored v2 regeneration changes original source, while all four owner overrides survive. Published v1 stays independent of unsaved/draft/regenerated changes.
- Explicit publishing appends a new publication entry. An explicit rollback appends a distinct history entry for an earlier public version **without resetting the current v2 draft**. The PHP layer independently checks a narrow allowlist, stable HTML tag/ID pairs, alt/CSS token and in-page fragment existence; this **regex-based validation is not general HTML parsing or a production trust sanitizer**. Do not assume safe arbitrary AI-site HTML.
- `flock` and compare-and-swap expected generation protect this simulated single-machine writer. Stale generation, duplicate initialization, invalid owner values, dangerous URLs, missing/retagged stable HTML targets, removed alt/CSS, source re-generation dropping owner overrides, and forged internally consistent edits to old publication history are refused. Actual PHP source file bytes, type-limited data and JSON-only CLI interface are exercised across process boundaries.
- Hash-checked `current.json` and `last-good.json`: crash injected after backup before current swap leaves current unchanged; corrupt current falls back to last-good; explicit restore re-creates current at a higher storage generation; both invalid copies **fail closed**. **New negative limitation:** last-good can lag by one transaction, so recovering it after last-current damage **may lose the most recent successful publication/rollback**. There is no independent append-only remote journal, durable backup service or fsync/power-failure guarantee. SHA256 detects accidental corruption **not intentional attacker tampering**.
- Real Chromium from the **PHP-persisted, freshly reloaded** v2 source shows owner text escaped, edited CTA href/alt, computed CSS gutter 40px, new reordered card source; independent published v1 retains default text/order; original mobile grid 1 column, H1 36px, reduced motion. Untrusted JS/forms are disabled, **zero network requests**. Not original site script interactivity parity.

**Failures resolved in CI:** First run put a Chromium test in PHP-only `durability` job without installed `playwright-core`; moved it to dependency-installed mixed-site-trust. Second failure was a negative test that inconsistently changed only historical entry instead of historical entry AND published pointer, yielding earlier rejection. Revised test mutates both consistently to reach the immutable-history check. Final commit passed full 4/4 CI. No uncontrolled live access.

## Implication / next priorities

This fills the **research integration gap** between v1.28's *memory-only* original-source editing and prior separate PHP file durability: the same original source, vetted edits, draft/publication/rollback are now persisted and re-rendered across PHP CLI processes and Chromium. This is still not a real CMS, not production multiwriter/storage protection, no formal PHP source DOM parser, no untrusted full JS support, no independent second-model source+manifest and no live shared hosting tests.

**Stage 1 per approved ROADMAP** is an open-source foundations **selection research stage**, not stage 3–10 product engineering. Future work must converge to an owner-ready quantified foundation recommendation (preferred / fallback / libraries, licensing/security/effort), disclose untested independent LLM and hosting cases, and obtain OWNER approval. A **genuinely independent second-model source AND separately produced editable manifest** would significantly improve decision confidence; if tools/provider access are missing, record it as unverified rather than indefinitely expanding Stage 1. Production persistent history, full contracts, generic behavior conversion, external anti-replay trust and eventual real hosting implementation belong to subsequent authorized stages.
