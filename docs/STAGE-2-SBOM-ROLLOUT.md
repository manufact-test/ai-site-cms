# AI Site CMS — Stage 2 machine SBOM, licensing and disposable offline rollout (v1.37)

**Date:** 2026-10-18. **Scope:** technical safety rehearsal and compliance inventory for an **internal, non-production, empty-CMS foundation**. Stage 2 is **IN PROGRESS / NOT ACCEPTED**. This is not a production updater, publisher-authenticated distribution, full-site backup or admin panel.

## Actual source implementation

1. `cms/tools/generate-compliance.cjs` reads committed `cms/composer.lock` and `cms/editor/package-lock.json`. It rejects unexpected lock shapes, package counts, unsupported declared licenses, missing version/integrity/source pins or missing/unsafe installed PHP LICENSE files. Emits deterministic machine-readable **CycloneDX 1.5 JSON component inventory** `private/compliance/sbom.cdx.json`: **43 library entries = 14 Composer shipped PHP runtime + 29 npm lock entries** (including optional platform packages not installed/shipped). The npm scope property distinguishes Jedison browser-runtime from build-time/dev-only packages.
2. `private/compliance/THIRD_PARTY_NOTICES.txt` copies installed upstream license texts for all 14 Composer PHP runtime packages and retains the **literal Jedison MIT copyright/license notice** already tracked in `cms/editor/THIRD_PARTY_LICENSES.txt`. `compliance-index.json` records counts and notice checksum. This is evidence of lock metadata and bundled license files, not an independent legal opinion, audited complete NOTICE attribution, SPDX license scanner, vulnerability-free attestation, or publisher signature.
3. `cms/release.json` pins the deliberately prerelease version **0.2.0-stage2.1**, channel `internal-laboratory`, and `productionReady:false`. `cms/tools/build-internal-package.cjs` now requires that version, includes the three compliance evidence files **outside webroot**, produces manifest format `ai-site-cms-internal-stage2-v2` with `releaseVersion`, verifies all file size/SHA256/inventory and SBOM/notice counts. At CI, package includes **429 files**; editor assets stay under `private/` only; runtime does **not** need Composer or Node installed on the PHP host.
4. `cms/tools/lab-versioned-rollout.cjs` implements **disposable OS temp-directory only** immutable release slots and a local `active.json` pointer switched using same-filesystem rename. It checks expected current version, verifies complete staged package before switch and previous slot before explicit rollback; refuses duplicate version slots, invalid version/path, corrupt pointers and missing/corrupt artifacts. `cms/tools/test-lab-rollout.cjs` exercises two synthetic versions, including expected failure before and after activation and subsequent rollback. **No application reads that pointer in production**; not a real installed updater or live site cutover.
5. All existing public boundaries remain: `GET /api/health` 200 and test-only publish/private-editor/vendor routes 404; no admin endpoints, no editing/publishing, no DB migrations invoked by rollout.

## Explicit safety boundaries

- All release steps so far run on **GitHub Actions ephemeral runner / disposable OS temp directory**, not on Hostinger, CELIKOM or another customer site. No actual host read-only check or deploy permission has been granted.
- Version-slot demonstration is a **code-only pointer simulation**. No host-specific filesystem atomicity test, concurrent worker test, read-only deployment approval, distribution signature/key trust, artifact authenticity, archive safe extraction, rollback across multiple PHP processes, zero-downtime site cutover or public server switch wiring. **No automatic live upgrade**.
- Most importantly, **no production DB backup / transactional data migration rollback / content media revisions restoration**. MySQL DDL is not assumed transactional. Earlier FoundationSnapshot stores only site ID, migration v2 and storage generation of an empty CMS.
- SBOM is a dependency **component ledger** from locked metadata and installed license texts: 29 npm entries include many optional packages not shipped, not 29 runtime browser dependencies. Third-party audit/policy, notices for future assets, CI provenance authentication and advisories require independent review before any production release.
- Full Stage2 acceptance remains blocked by real shared-host compatibility + permitted smoke on a separate empty installation, safe signed/authenticated distribution, install/upgrade/rollback validated against actual persistent state, and broader product layers reserved for later stages.
- **No MVP, no production claim.** 193 requirements = 135 mandatory + 42 desirable + 16 excluded; **0/135 mandatory PRODUCT accepted**; Stage0 and Stage1 accepted, Stage2 not accepted, Stage3 not started.
