# AI Site CMS — офлайн-демонстратор интерфейса (Stage 2)

> **Только дизайн-лаборатория, не полноценная CMS и не финальный дизайн.**
> Нет авторизации, реального Hostinger, API, MySQL-контента, публикации, рабочих форм или отправки данных.
> Stage 2 НЕ принят, Stage 3 НЕ начат. Задача — увидеть, как должен работать редактор, а не выдавать демо за готовый продукт.

## Как открыть без сборки

1. Откройте последний успешный workflow **Stage 2 static Jedison editor (internal CI only)** на GitHub Actions.
2. Скачайте артефакт `ai-site-cms-stage2-owner-click-to-open-kit`, распакуйте.
3. Откройте `stage2-preview/index.html` двойным щелчком в Chrome или Edge.
4. Для работы с локальными черновиками лучше использовать один и тот же браузер и папку.
5. Для надёжного бэкапа экспортируйте JSON через меню «Проект». Скачанный ZIP с HTML — лишь локальная демонстрационная копия, не production-деплой.

**Второй способ из исходников:** `cd cms/editor && npm ci && npm run build`, затем открыть `cms/stage2-preview/index.html`.
Node.js 22+ нужен только для первичной сборки, не для работы скачанного owner review ZIP.

## Что работает в текущем проекте v3

- Три готовых многостраничных примера и **11 типов секций**, редактируемых через закреплённый Jedison 1.27.1.
- Отдельные обзор и редактор страницы, дерево страниц, поиск секций, выбор секции кликом по странице, инспектор справа, три темы и адаптивный предпросмотр (ПК, планшет, телефон).
- Создание и дублирование страниц, изменение адреса/Title/Description, сортировка страниц, копирование и перестановка секций, базовый SEO-список замечаний.
- **Общие настройки**: подпись под названием сайта, текст в подвале, глобальное включение меню.
- **Страница вне меню**: остаётся в проекте и в HTML-экспорте, но исчезает из навигации. Главная остаётся в меню.
- **Скрытые секции**: сохраняют текст/настройки и редактируемость, но отсутствуют в обычном предпросмотре и экспортированном HTML. Минимум одна секция на страницу остаётся видимой. В режиме редактирования одного блока скрытую секцию можно открыть.
- Локальные черновики (до восьми версий), undo/redo, JSON экспорт/импорт и старые проекты формата v2 автоматически мигрируют в v3.
- Экспорт многостраничного автономного HTML-сайта со связанными страницами, корректными SEO title/description и JSON-бэкапом. Это **не публикация**; пользовательские файлы в браузере не загружаются в сеть.
- Заметки к блокам и страницам с выгрузкой единым Markdown-файлом.

## Границы и безопасность

Данные форм и кнопок никуда не отправляются: это отключённые макеты. Все редактируемые строки экранируются; iframe и HTML-экспорт отключают JS и сетевые подключения. Демо-заготовки содержат вымышленные примеры; никаких клиентских сайтов или настоящих ключей здесь нет.

Формат `ai-site-cms-stage2-multipage-preview-v3` — **локальный контракт демо**, а не утверждённая схема будущей Stage3. Переход к реальной CMS/Hostinger невозможен без формальной приёмки Stage 2, отдельно разрешённых операций на целевом хостинге и проверки безопасности.

## Разработка и проверка

После сборки Jedison выполняется один реальный браузерный сценарий:

```bash
cd cms/editor
node tests/stage2-preview-smoke.cjs
```

Сценарий включает создание страниц, редактирование, скрытие секций и страниц из меню, настройки сайта, локальное сохранение, миграцию v2, автономный ZIP, владельческий ZIP, заметки и отсутствие HTTP запросов. Существующие CI проверки безопасности НЕ отключать и НЕ заменять новыми тестами ради количества.

**Правило работы:** крупные взаимосвязанные возможности, затем один критический браузерный сценарий и существующие CI. Не тратить большую часть разработки на проверку функций, которых ещё нет.


## v1.53 — независимые локальные сайты и архив рабочего портфеля

Селектор «САЙТ» в шапке переключает до восьми самостоятельных сайтов с независимыми версиями, страницами, контентом и замечаниями. В меню «Проект» доступны «Новый сайт», «Копировать текущий сайт», «Удалить текущий сайт», экспорт/импорт одного сайта и «Скачать архив всех сайтов» / «Восстановить сайты из архива». В `ai-site-cms-all-local-sites-backup.json` включены полные сохранённые версии и замечания всех локальных сайтов; при восстановлении исходные сайты не перезаписываются. Внешних запросов нет; архив хранится в открытом JSON и может содержать клиентские контакты/фото — храните его безопасно. Это не серверный бэкап production CMS и не publish.


## v1.54: кадрирование фото в локальном макете

В iframe на hero, story, services и catalog выберите «✎ Фото». Можно загрузить локальное JPG/PNG/WebP, выбрать общий файл, изменить ALT, задать точку кадрирования кликом, двумя ползунками или пресетами. ALT и focus общие для одного медиафайла во всех его применениях; отсутствующий в старом проекте focus означает центр. Сохранение, Undo/Redo, архив JSON и экспорт ZIP сохраняют фокус. Внешних сетевых вызовов нет. Preview использует локальный Blob CSS, чтобы родительский CSP не блокировал оформление. Это НЕ CMS production/publisher.
