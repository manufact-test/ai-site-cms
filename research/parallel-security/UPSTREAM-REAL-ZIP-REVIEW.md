# Direct upstream source ZIP vs signed Git objects (2026-10-21)

**Threat:** a signed annotated Git tag pins Git objects, but **does not itself prove** the ZIP delivered by the Composer/GitHub archive endpoint contains those bytes. Lockfile references and hashes are metadata, not per-file installed-source proof.

**Independent verification (read-only; public GitHub only):** `sodium-real-zip-proof.mjs --online` performs an actual HTTPS GET to the pinned GitHub API endpoint and requires the *only* redirect be to `https://codeload.github.com/paragonie/sodium_compat/legacy.zip/3246b36803c177847e677862fedeb7f937869adb`. It bounds ZIP length/decompressed bytes, parses ZIP central/local headers itself using Node built-ins (no ZIP extraction or running third-party code), rejects traversal, symlinks, ZIP bombs, altered CRC/headers, unexpected root/revision and archive file additions/deletions, and verifies **all 78 archive file bytes** against their original `git hash-object` SHA-1s. Those IDs independently trace through **all 211 recursive Git entries** to the pinned tag commit Git tree, which GitHub reports protected by a valid signed tag (see `UPSTREAM-SIGNED-GIT-SOURCE-REVIEW.md`). The executed code is our isolated verifier only.

Expected successful proof: `REAL Composer ZIP bytes verified against signed-tag Git source PASS 78 files; no PHP execution, independent PGP owner trust or production approval`. It also reports actual ZIP SHA-256 for retention. If the network is unreachable, mark **BLOCKED** and never claim the ZIP was validated. If an actual fetched ZIP is malformed or source content differs, mark **FAILED**, not blocked. Offline parser abuse cases: `sodium-real-zip-regression.mjs` — synthetic ZIPs do not imply real-source proof.

No code or ZIP is installed, no production Composer lock mutated, no Hostinger or secrets, no plugins/scripts. This is NOT independent PGP signer identity verification, independent vulnerability review, ISC attribution/legal approval, PHP cryptography audit or production acceptance. GitHub tag verification indicates tag-signature cryptographic validity per GitHub, not separate signer trust. Source identity alone is not a guarantee of safe cryptography.
